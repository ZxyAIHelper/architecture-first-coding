# 整体架构案例发布方案

## 边界与归属

- skills/architecture-first-coding：原版 skill 与参考，保持内容和字节不变。
- README.md 与 README.zh-CN.md：中英文介绍、文字安装说明、案例导航。
- examples/README.md：如何把需求转成职责、所有者、契约、数据流及验收证据。
- examples/survivor/README.md：《余烬庭院 · 二十波》整体架构。涵盖五层与最外侧装配、局内阶段、战斗编排、奖励、装备经济、资料与轨迹边界。
- examples/mall/README.md：《街坊商场》整体架构。涵盖界面、经营会话、经营局、设施与通路、账本、员工、客流交通、成长事件、存档和平台边界。
- examples/README.en.md 与两个案例的 README.en.md：独立英文架构说明，英文入口默认链接这些版本。
- examples/diagrams：提交中英文各三张 PNG，分别为 skill 应用流程及两个游戏的整体职责图。英文页面仅嵌入带 -en 后缀的英文图片。图按系统族聚合，不表示穷举源码导入或全部运行时边。

## 内容与图示设计

实线箭头表示图示粒度上的主动调用或查询方向；返回数据属于原调用结果，不画作下层主动反向调用。装配入口单列，避免被误读为核心层全局上下文。核心系统族是责任分组，不要求每组恰好对应单个类或各组之间相互独立。

正文提供系统与权威状态表、至少三条跨模块链路、生命周期与失败边界，以及如何用 skill 做出这些设计的逐步示范。契约用自然语言表格描述请求内容、所有者与结果，不包含代码或伪代码。

## 执行顺序与验证

先同步规格，再只读核对两项目有效架构计划、装配入口及相关所有者。重写案例和仓库入口，移除两个模型及验证/CI 文件。用仓库外的临时绘图工具生成 PNG，不提交生成器。

发布前检查文件清单、链接、图片尺寸与压缩预览、旧名和代码块残留、敏感内容及原版 skill 字节。只有文档与架构图，不运行原游戏回归，不沿用已删除模型的测试通过数作为本次验收。提交并正常推送现有公开仓库，更新仓库简介并核对远端 HEAD。

英文修订额外检查四份英文 Markdown 无汉字、英文图片的所有标签均为英文，并保留原版中文 skill 不变；原版入口以英文明确标注为 Chinese，避免将其冒充已翻译版本。仓库简介使用英文。
